# TeamFinder

**TeamFinder** — веб-платформа для поиска единомышленников и сборки команд под
pet-проекты. Разработчики, дизайнеры и другие специалисты регистрируются,
рассказывают о себе, публикуют идеи проектов, отмечают необходимые навыки и
присоединяются к чужим инициативам.

## Возможности

- Регистрация и аутентификация по email и паролю; смена пароля из меню профиля.
- Публичный профиль пользователя: аватар (генерируется автоматически по первой
  букве имени), контакты, краткое «о себе», список созданных и поддержанных
  проектов.
- Редактирование профиля: имя, фамилия, аватар, телефон (с валидацией формата
  `+7XXXXXXXXXX`/`8XXXXXXXXXX`), GitHub-ссылка (с проверкой домена).
- Каталог проектов с пагинацией (12 на страницу), сортировкой «новые сверху»
  и сеткой карточек.
- Карточка проекта: автор, дата публикации, описание, статус (открыт/закрыт),
  список участников, кнопки «Присоединиться/Покинуть», «Завершить проект»,
  «Поделиться ссылкой».
- Создание, редактирование и завершение собственных проектов;
  администратор может править и удалять любые.
- Блок **«Необходимые навыки»** у каждого проекта: владелец добавляет/удаляет
  теги через автодополнение без перезагрузки страницы (AJAX + CSRF), может
  создать новый навык прямо из интерфейса.
- Фильтрация проектов по навыкам через `?skill=<название>` — над сеткой
  отображается панель тегов, активный подсвечивается, есть ссылка «Сбросить».
- Каталог пользователей с пагинацией и кнопкой «Посмотреть контакты».
- Админка Django: миниатюры аватаров в списке пользователей, удобное
  редактирование участников и навыков проектов.

## Стек технологий

- **Backend**: Python 3.11+, Django 5.2
- **БД**: PostgreSQL 16, драйвер `psycopg[binary]` 3.x
- **Шаблоны**: Django Templates
- **Статика**: WhiteNoise (раздача в продовом режиме)
- **Изображения**: Pillow (генерация буквенных аватаров)
- **Конфигурация окружения**: python-decouple
- **Контейнеризация**: Docker, Docker Compose
- **Frontend-логика**: ванильный JavaScript (`static/js/skills.js` для
  автодополнения навыков и AJAX-операций)

## Структура репозитория

```
team_finder/        # настройки и корневые URL Django
projects/           # приложение проектов: модели, формы, views, миксины,
                    #   константы, шаблонные теги
users/              # приложение пользователей: модель User, менеджер,
                    #   формы, аватары, services, константы
templates_var3/     # HTML-шаблоны
static/             # CSS, JS, иконки
media/              # пользовательские загрузки (аватары)
docs/               # внутренняя документация по этапам разработки
```

## Переменные окружения

Перед запуском нужно создать файл `.env` в корне репозитория. Готовый
шаблон лежит в `.env_example`:

```bash
cp .env_example .env          # Windows: copy .env_example .env
```

| Переменная           | Назначение                                   | Пример                      |
|----------------------|----------------------------------------------|-----------------------------|
| `DJANGO_SECRET_KEY`  | Секретный ключ Django                        | `change_for_safety`         |
| `DJANGO_DEBUG`       | Режим отладки (`True`/`False`)               | `True`                      |
| `ALLOWED_HOSTS`      | Разрешённые хосты, через запятую             | `localhost,127.0.0.1`       |
| `POSTGRES_DB`        | Имя базы данных                              | `team_finder`               |
| `POSTGRES_USER`      | Пользователь БД                              | `team_finder`               |
| `POSTGRES_PASSWORD`  | Пароль пользователя БД                       | `team_finder`               |
| `POSTGRES_HOST`      | Хост БД (для Docker — `db`)                  | `localhost`                 |
| `POSTGRES_PORT`      | Порт БД                                      | `5436`                      |

В продовом режиме (`DJANGO_DEBUG=False`) автоматически включаются стандартные
валидаторы паролей Django.

## Запуск через Docker (рекомендуется)

```bash
cp .env_example .env          # Windows: copy .env_example .env
docker compose up --build
```

Контейнер `web` сам выполнит `migrate`, `seed`, `collectstatic` и запустит
сервер. Приложение будет доступно на <http://localhost:8000/>.

## Запуск локально

Требуется Python 3.11+ и Docker (для PostgreSQL).

```bash
python -m venv venv
# Windows
venv\Scripts\Activate.ps1
# Linux / macOS
# source venv/bin/activate

pip install -r requirements.txt
cp .env_example .env

docker compose up -d db
python manage.py migrate
python manage.py seed
python manage.py runserver
```

После этого приложение поднимется на <http://127.0.0.1:8000/>.

## Тестовые учётные записи

Создаются командой `python manage.py seed`. Пароль у всех — **`password`**.

| Email                | Имя               |
|----------------------|-------------------|
| `alice@example.com`  | Алиса Иванова     |
| `bob@example.com`    | Борис Петров      |
| `carol@example.com`  | Каролина Сидорова |
| `dan@example.com`    | Даниил Кузнецов   |

Полезные команды:

```bash
python manage.py seed --reset         # пересоздать тестовые данные
python manage.py createsuperuser      # суперпользователь для админки
python manage.py test                 # запустить тесты
```

Админка: <http://127.0.0.1:8000/admin/>.
